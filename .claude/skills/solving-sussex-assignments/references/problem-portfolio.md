# Problem portfolios (POF)

A portfolio of worked problems accumulated across the module, usually the dominant assessment.

**Next up: Module 3 Assessment 2 - 70% of the module, 2100 words, due Monday of Week 8 at 10:00 UK.**

## Start early; this is an accumulation, not a sprint

The module intro is explicit:

> "Portfolio problems: having had an opportunity to work collaboratively on solving problems with
> your peers, additional problems are provided each week for your Independent study. These form
> part of your Assessment 2: Portfolio. You are encouraged to develop these problems throughout
> the module independently as part of your portfolio assessment."

So the right default is a running document that grows weekly, not a document begun when the brief
drops. When invoked mid-module:

1. Find which weekly problems are designated portfolio problems.
2. Check whether a running file already exists before starting a new one.
3. Work the current week's problems into it now, while that week's lecture is fresh.
4. Track which weeks are in scope. Scope exclusions are real and have applied before: in Module 1,
   the portfolio covered weeks 1-6 and week 7 was explicitly excluded.

## Word counts in a maths portfolio

Ask what counts. Equations and workings usually do not count toward a prose word limit, but
confirm against the brief rather than assuming. If the limit is tight, the prose to protect is the
exposition and the closing sentences - those carry the marks (`marking-rules.md`).

## Presentation compounds here

Every rule in `marking-rules.md` applies once per problem, so a portfolio multiplies both the gain
and the loss. The Module 1 tutor's closing-sentence comment was made specifically about the
portfolio: *"in the portfolio it will be appropriate to write a sentence of text to help close off
the final answer"*. Build the closing sentence in from the first problem rather than retrofitting
it across twenty.

Keep one consistent document structure from the start - the same box layout, the same six-step
shape per problem. Retrofitting structure across an accumulated portfolio is far more work than
starting with it.
