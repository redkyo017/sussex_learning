# Week companion - the required shape

One per lecture week. It decodes *that* lecture; it is not a pre-read and not a summary.
Baseline agents produced "what to know before week N" pages instead - those teach nothing the
lecture does not already say and leave the learner stuck at the same skipped step.

```markdown
# Week KK Companion - <lecture title>

**Built on:** Day N, Day M (the moves this week uses)
**Feeds:** Assessment 1 / Portfolio / neither

## 1. Read these first (Pass 0)
The week's task and portfolio problem *types* in one line each, by number. No solutions.

## 2. What the lecture is doing, in one picture
Three to five sentences: the physical or conceptual story, before any symbol.

## 3. Notation decoder
| Symbol as written | Read it as | Move it comes from (Day N §x) |
Every symbol the lecture introduces or assumes. This is the table the learner keeps open.

## 4. Skipped steps, expanded
For each derivation the lecture compresses: equation number, the gap, the missing lines.
Name the move used at each line. This section is the reason the companion exists.

## 5. Clones
Two to four worked problems of the same *type* as the week's tasks, with
**different numbers, functions and operators** (see clone-integrity.md). Each:
problem -> hint -> solution sketch in six-steps form -> closing sentence.

## 6. Cold attempt
One fresh variant, hint only. The learner attempts before opening §5.

## 7. Confusion log prompts
Three questions the learner answers in writing after the lecture.
```

For qualitative modules, §3 becomes a *framework decoder* (framework -> inputs -> outputs ->
failure mode -> where the week uses it), §4 becomes *arguments the reading leaves implicit*, and
§5 becomes *applications to a running case* that is not the assessed one.
